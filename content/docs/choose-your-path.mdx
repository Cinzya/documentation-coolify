# Choose your path
Coolify can be used in two ways:
- [Self-hosted](/start-with-self-hosted) - you run and maintain the Coolify instance yourself
- [Coolify Cloud](/start-with-cloud) - the Coolify team runs and maintains the Coolify instance for you

In both models, your apps, databases, and services still run on your own servers.


## Why this choice matters
Both paths give you the same core product experience, but they differ in **who owns operations for the Coolify instance**.

This decision affects:
- how much platform maintenance you handle
- how fast you can get started
- how much control you want over updates and operations
- how much time you want to spend troubleshooting platform-level issues


## What stays the same in both paths
No matter which path you choose:
- you bring your own servers
- your workloads run on your servers using Docker
- you get the same Coolify feature set
- there is no Cloud-only feature paywall


## Quick recommendation
- Choose [Self-hosted](/start-with-self-hosted) if you want maximum control and are comfortable managing platform operations.
- Choose [Coolify Cloud](/start-with-cloud) if you want less operational overhead and a faster path to production.


## How to decide
Use these questions:

1. Do you want to manage Coolify updates, availability, and instance backups yourself?
    - If **yes**, self-hosted is likely the right fit.
    - If **no**, Coolify Cloud is usually the better fit.

2. Is your priority full infrastructure ownership over convenience?
    - If **yes**, self-hosted is a better match.
    - If **no**, Coolify Cloud is the smoother option.

3. Do you want the fastest onboarding with the least control-plane setup work?
    - If **yes**, Coolify Cloud is usually the fastest path.
    - If **no**, self-hosted gives you deeper ownership from day one.


## Path A: [Self-hosted Coolify](/start-with-self-hosted)
Choose this if you want full control of the Coolify control plane.

You handle:
- installation and upgrades
- instance backup and restore planning
- availability and operational maintenance

This path is best for:
- people comfortable with Linux server operations
- teams that want to control when and how updates are applied
- operators with internal standards for security and change management
- users who want to use Coolify for free (excluding their own server/infrastructure costs)

Choose self-hosted if your main goal is ownership and control.


## Path B: [Coolify Cloud](/start-with-cloud)
Choose this if you want the same Coolify experience with less control-plane maintenance.

The Coolify team handles:
- hosting and maintaining the Coolify instance
- upgrades and operational maintenance of that instance
- managed backup of the Coolify Cloud instance

You still handle:
- your own servers
- your app and database runtime security
- your workload backup and restore strategy

This path is best for:
- beginners who want the quickest start
- teams who prefer to focus on shipping apps instead of operating the platform layer
- users who want a managed control plane but still keep workload ownership
- users who are comfortable paying for managed convenience

Choose Coolify Cloud if your main goal is speed and lower operational overhead.


## Cost and responsibility summary
- **Self-hosted**: no Coolify license fee, but you manage the Coolify instance yourself.
- **Coolify Cloud**: paid managed service for the Coolify instance, while you still bring and secure your own servers.

For the full breakdown, read: [Self-hosted vs Coolify Cloud](/core/selfhosted-cloud-comparison)
