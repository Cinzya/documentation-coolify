# Common CLI workflows

These examples assume that `coolify context verify` succeeds. Replace every placeholder UUID and name with a value from your selected Coolify team.

## Inspect resources

Start with read-only inventory commands:

```sh
coolify server list
coolify project list
coolify resource list
coolify app list
coolify database list
coolify service list
```

Use `get` with a resource UUID for details:

```sh
coolify app get <application-uuid>
coolify database get <database-uuid>
coolify service get <service-uuid>
```

Coolify resource commands use UUIDs. Team commands are the exception and use numeric team IDs.

## Deploy a resource

Deploy one resource by UUID or by its name:

```sh
coolify deploy uuid <resource-uuid>
coolify deploy name <resource-name>
```

Deploy several named resources together:

```sh
coolify deploy batch api,worker,frontend
```

Inspect the deployment and cancel it when necessary:

```sh
coolify deploy list
coolify deploy get <deployment-uuid>
coolify deploy cancel <deployment-uuid>
```

Run `coolify deploy <command> --help` before using flags such as `--force`, preview deployment IDs, or image-tag overrides.

## Read and follow logs

```sh
coolify app logs <application-uuid> --lines 100
coolify app logs <application-uuid> --follow --show-timestamps
coolify database logs <database-uuid> --follow
coolify service logs <service-uuid> --sub-service-name <name>
```

For a Docker Compose application, add `--service <name>` to select one service container.

## Manage environment variables

Create one application variable:

```sh
coolify app env create <application-uuid> --key API_URL --value https://api.example.com
```

Sync a file:

```sh
coolify app env sync <application-uuid> --file .env.production
```

The sync command updates matching keys and creates missing keys. It does not delete variables that are absent from the file. Service and database resources provide corresponding `env` command groups.

<Callout type="warning" title="Keep secrets out of command history">
Arguments may be stored in shell history or CI logs. Load sensitive values through your automation platform's secret handling and review log redaction before running commands with secret flags.
</Callout>

## Use JSON in automation

All commands accept a global output format:

```sh
coolify --format json resource list
coolify --context production --format json deploy list
```

- `table` is the default human-readable output.
- `json` is compact and intended for scripts.
- `pretty` is indented JSON for inspection.

Sensitive values remain hidden unless both the API token can read them and `--show-sensitive` is passed. Do not enable `--show-sensitive` in shared logs.

A command exits with a nonzero status when it returns an error, so CI jobs can stop on failed operations. Use `--debug` only while diagnosing a request because debug output can add operational details to logs.
